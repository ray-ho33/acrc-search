# Phase 분리 계획 — 고충처리 자료 검색 지원 시스템

> Phase 1만으로도 "쓸 만한 검색 도구"가 되어야 한다.
> 각 Phase는 **실제 배포 + 실제 데이터로 검증 + 사람 피드백** 받기 전까지 끝난 게 아니다.

## Phase 1 (MVP) — 의결례 시맨틱 검색 웹앱

> **이것만으로도 실제 데모로 쓸 수 있는 검색 도구가 된다.**

### 포함 기능

- [ ] Next.js 14 + TypeScript + Tailwind 프로젝트 셋업
- [ ] Supabase 프로젝트 생성, pgvector 확장 활성화, `documents` / `document_embeds` / `feedback` 테이블 생성
- [ ] 자료 수집 스크립트 (이전 레포 `acr-download.mjs` 재사용·이식)
  - 법제처 Open API → 권익위 의결례 JSON 다운로드
  - Supabase `documents`에 적재
- [ ] 임베딩 생성 스크립트 (이전 레포 `gemini-embed.mjs` 재사용)
  - Gemini `gemini-embedding-001` (`RETRIEVAL_DOCUMENT`)
  - L2 정규화 후 `document_embeds.embedding`에 저장
- [ ] 검색 API 라우트 (`/api/search`)
  - 쿼리 임베딩 (`RETRIEVAL_QUERY`)
  - pgvector 코사인 유사도 Top-20
- [ ] 검색 UI (`/`)
  - 검색창, 결과 카드 리스트, 자료 종류·연도 필터, 로딩 상태
- [ ] 상세 화면 (`/documents/[id]`)
  - 전문, 메타데이터, 원문 링크, 환류 메모 입력
- [ ] 환경변수 설정 (`.env.example` 작성)
- [ ] Vercel 배포 + Supabase 연결
- [ ] 의결례 ≥ 500건 인덱스 보유

### 완료 기준 (Phase 1 Done)

- 배포된 URL을 처음 보는 사람이 검색어를 넣어 의결례를 찾아 원문 링크로 이동할 수 있다.
- 검색 응답 시간 P95 ≤ 2초.
- 환경변수 누락 시 명확한 오류가 표시된다.
- API 키가 Git에 들어가지 않음 (히스토리 검사).
- 조사관 또는 동료 1명에게 시연 후 피드백 ≥ 1건 수집.

> **장점**: 빠르게 결과물 확인 가능, 의결례만으로도 실용성 검증 가능
> **단점**: 아직 자료 4종 통합 아님, AI 요약 없음, 즐겨찾기 없음

## Phase 2 — 자료 4종 확장 + 유사 사례 추천

> Phase 1이 안정적으로 돌아간 후에 추가.

### 포함 기능

- [ ] 자료 출처 3종 추가
  - [ ] 법제처 유권해석 (법제처 Open API)
  - [ ] 행정심판 재결례 (행심위 / API 확인 필요)
  - [ ] 대법원 판례 (대법원 / API 확인 필요)
- [ ] 검색 결과 카드에 "출처 구분" 컬러 칩 추가
- [ ] 유사 사례 추천 (`/documents/[id]` 페이지)
  - 현재 자료의 임베딩 ↔ 다른 자료들의 코사인 유사도 Top-5
- [ ] 즐겨찾기 (`bookmarks` 테이블 활성화)
- [ ] 검색 로그 수집 (`search_logs` 테이블)
- [ ] 자동 갱신 (cron 또는 Vercel Cron)
  - 매일 새 자료 증분 수집 → 임베딩 → 적재
- [ ] 검색 결과 BM25 + 코사인 하이브리드 (가중치 실험)

### 완료 기준 (Phase 2 Done)

- 4종 자료가 한 화면에서 검색되고 출처가 구분되어 표시된다.
- 자료 상세 화면에서 "이 사건과 비슷한 사례 5건"이 보인다.
- 자동 갱신이 매일 동작하고 실패 시 로그가 남는다.
- 조사관 3명에게 1주 시범 사용 → 피드백 수집.

> **장점**: 기획서 핵심 가치(통합 검색) 완성, 환류 데이터로 검색 개선 사이클 시작
> **단점**: Phase 1 안정화 필수

## Phase 3 — AI 요약 + 인증 + 관리자

> 고급 기능. 없어도 앱은 쓸 만함.

### 포함 기능

- [ ] AI 요약 (Gemini `gemini-pro` 또는 `gemini-flash`)
  - 결정문 전문 → 3~5문장 요약
  - **가드레일**:
    - 시스템 프롬프트에서 "결론은 내리지 마라" 명시
    - 결론형 문장 (예: "~로 보여진다", "~가 타당하다") 차단 룰
    - 출력 형식 검증 (JSON 스키마)
    - 사용자 화면에 "AI 생성, 원문 확인 필수" 고지
- [ ] 인증 (Supabase Auth 매직링크)
  - `.env`에 사전등록 명단 CSV 또는 Supabase `users` 테이블 INSERT
  - 이메일 도메인 화이트리스트 (예: `@acrc.go.kr`)
- [ ] 관리자 메뉴 (`/admin`)
  - 사용자 관리 (가입 승인/거부)
  - 자료 검수 큐 (자동 수집 → curator 검수 → 공개)
  - 신고 처리 큐 (Phase 4)
- [ ] 감사 로그 (`audit_logs`)
- [ ] RLS 활성화
  - `documents` 읽기: 인증된 사용자만
  - `feedback` 수정/삭제: 본인 또는 admin만
- [ ] 환류 데이터 활용
  - 👎 누적 시 curator 검수 큐로 자동 진입
  - 환류 50건 이상 자료는 추천 가중치 상향

### 완료 기준 (Phase 3 Done)

- 미인증 사용자는 검색 페이지에 접근할 수 없다.
- AI 요약이 "결론형 문장"을 출력하지 않는다 (가드레일 통과율 ≥ 95%).
- 관리자가 자료 검수 큐에서 자료를 공개/숨김 처리할 수 있다.
- 감사 로그가 90일 이상 보존된다.
- 외부 보안 점검 1회 통과.

> **장점**: 정식 운영 가능 수준, 환류 사이클 작동
> **단점**: G-Cloud 이전 시 일부 구조 재설계 필요할 수 있음

## Phase 4 (참고만, 본 PRD 범위 외) — 정식 시스템화

- G-Cloud 이전 (Supabase → G-Cloud Postgres)
- 망분리 환경 대응 (자체 임베딩 모델 또는 마스킹 후 외부 호출)
- ISMS-P / PIA 대응
- SIEM 감사 로그 연동
- 외부 침투 테스트

## 진척 체크 방식

각 Phase는 다음을 만족해야 "완료"로 표시:
1. 모든 acceptance criteria 체크박스 ✅
2. 배포 URL이 실제로 동작
3. 실제 자료로 검증 (목업 데이터 아님)
4. 사람(조사관 또는 동료)에게 시연 후 피드백 1건 이상
