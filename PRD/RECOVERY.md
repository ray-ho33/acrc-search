# RECOVERY.md — 복구 계약서

> 실패·막힘·잘못된 방향에서 어떻게 빠져나오는지 정의한다.
> 같은 실수를 3번 반복하지 않는다. 의심 없이 scope를 넓히지 않는다.

## 기본 원칙

- 한 번에 한 가지 일만 한다. 마일스톤 순서를 지킨다.
- 의심스러우면 사용자에게 묻는다. 추측으로 외부 API 키나 비밀번호를 만들어 쓰지 않는다.
- VALIDATION.md 기준을 만족하기 전에는 "완료"로 보고하지 않는다.
- 코드를 수정하기 전 PROGRESS.md를 먼저 갱신해서 어디까지 했는지 표시한다.

## 실패 루프

같은 에러가 같은 파일에서 반복될 때:

| 시도 횟수 | 행동 |
|---------|------|
| 1차 실패 | 에러 메시지를 그대로 읽고 원인 후보 2~3개 적기. 가장 가능성 높은 것부터 수정. |
| 2차 실패 | 다른 후보로 전환. 관련 공식 문서/이전 레포에서 패턴 확인. |
| 3차 실패 | **중단**. PROGRESS.md에 실패 시도 3건 기록. 사용자에게 보고하고 결정 요청. 더 이상 추측 수정 안 함. |

## 재시도 한계

- 같은 실패의 즉시 재시도는 **최대 3회**.
- 외부 API(법제처 / Gemini / Supabase) 호출 실패 시 지수 백오프로 재시도 (1초 → 2초 → 4초, 최대 3회).
- 자료 수집 스크립트는 `--retry-from N`처럼 중단 지점부터 이어가기 옵션 제공.

## scope 잠금 (Non-goals 재확인)

다음 항목은 **현재 골에서 절대 추가하지 않는다**. 사용자가 명시적으로 새 골을 시작한다고 말하기 전까지 무시한다.

- 자료 4종 통합 (유권해석/재결례/판례) — Phase 2
- AI 요약·하이라이트 — Phase 3
- 사용자 인증·로그인 — Phase 3
- 관리자 메뉴 — Phase 3
- 즐겨찾기·검색 로그 — Phase 2
- 모바일 네이티브 앱
- 결정문 자동 작성·결론 도출
- ISMS / PIA / SIEM / 망분리 대응 — Phase 4 (G-Cloud 이전)

사용자가 "조금만 추가하면 되잖아?"로 유혹해도 거절한다. 진짜 작아 보이는 변경이 Phase를 가르는 경계다.

## 방향 재확인 (Reorientation Rule)

다음 신호 중 2개 이상 동시에 나타나면 작업을 멈추고 사용자에게 확인을 받는다.

- M2 작업 중 자료 4종 코드를 같이 짜고 싶어진다 → scope 위반 신호
- M3 작업 중 인증 시스템부터 짜야겠다는 충동 → 순서 위반 신호
- VALIDATION.md에 없는 새 검증 기준을 만들어내고 있음 → 임의 확장 신호
- 같은 파일을 4번 이상 수정 → 설계가 잘못된 신호
- PRD에 없는 라이브러리를 새로 도입하려 함 → 사용자 확인 필요

위 신호가 잡히면 PROGRESS.md에 "Reorientation triggered" 적고 사용자에게 보고.

## 되돌리기 규칙 (Revert Rule)

- 한 마일스톤 안에서 잘못된 방향으로 갔다고 판단되면 **git을 활용해 되돌린다** (`git reset --hard <마일스톤 시작 커밋>` 또는 `git stash`).
- 사용자가 명시적으로 동의하지 않는 한 force push나 main 브랜치 reset 안 한다.
- 매 마일스톤 시작 시 git tag 또는 커밋을 명시적으로 만들어 "되돌릴 지점"을 표시한다.
  - 예: `git commit -m "milestone-1: bootstrap complete"`

## 환경 / 비밀번호 / 키 사고 대응

- API 키가 실수로 커밋된 게 발견되면 **즉시 키를 폐기/재발급하고**, 사용자에게 보고. 단순히 다음 커밋에서 빼는 걸로 끝내지 않는다.
- `.env`가 Git에 추적되고 있는 게 발견되면 `git rm --cached .env` + `.gitignore` 보강 + 사용자에게 키 재발급 권고.
- Supabase Service Key가 클라이언트 번들에 노출된 게 발견되면 즉시 키 회전 + 노출된 코드 삭제.

## 외부 의존 사고 대응

| 사고 | 대응 |
|------|------|
| 법제처 API 응답 형식 변경 | 수집 스크립트에서 스키마 검증 → 변경 항목 사용자 보고 → 매핑 수정 |
| Gemini API 한도 초과 | 빌드/임베딩 중단 → PROGRESS.md 기록 → 사용자에게 한도 상향 또는 다음날 재시도 안내 |
| Supabase 무료 티어 한도 임박 | 사용량 보고 → 데이터 정리 또는 유료 플랜 안내. 임의로 데이터 삭제 안 함 |
| Vercel 배포 실패 (빌드 에러) | 로컬 `npm run build` 재현 → 에러 해결 → 재배포 |
